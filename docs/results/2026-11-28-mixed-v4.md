# mixed_v4: frontier_v3 + fable_v4 merged

Date: 2026-11-28. Branch `mixed-v4` (from `1e7e312`, the last `frontier_v3` commit). Config: `configs/mixed_v4.yaml`.
Compute: none. Every number below is a CPU replay of the shared model-call cache; no model call was made.

**mixed_v4 scores at least as well as both parents on all three benchmarks.** The ParseBench gain over
`fable_v4` is +0.28. RealDocBench is a tie with `fable_v4`, and olmOCR-bench is +0.04 over `frontier_v3`, which is well
inside that benchmark's ±0.9 interval.

## 2. What came from which branch

From **frontier_v3**:

- PDF-geometry table routing (`table_options.table_geo`);
- the Qwen3.5-122B-A10B 3-strip table re-read with its alignment guard (`tier2_tables`);
- the scan layout arbiter and blank-box drop (`pp_scan_arbiter`, `blank_drop`);
- prose-only PDF underlines (`format_options.underline_missing`: check underline 94.45, against 92.15 for fable_v4's
  `underline`);
- AcroForm clean-up (`form_options.acro_clean`);
- chart figures that hold a table taking the chart read (`tier2_chart_options.table_figures`, kept: section 3).

From **fable_v4**:

- the Qwen3.8-27B chart stack: thinking, prompt `v2b`, crops zoomed to 2048 px, the full vector hint, a plain re-read
  when the thinking read fails, and three reads voted cell by cell;
- the `caption: value` form rewrite: `prompt: kv`, the wide trigger, also run on the other reader's page;
- the text-layer reader selector (`select_options`), with word fusion and picture carry-over;
- the round-3 table repairs, except `merge_strict`.

neon's merge added `select_options.table_margin: 0.05`: on a page routed by table geometry, the selector needs a 0.05
margin to switch readers. It is kept as merged and was not measured separately.

The ruled-table underline guard from fable_v4 is in the code (`fixes/formatting.py`). It acts only where
`underline: true` runs on tables, which in mixed_v4 is the chart model's draft (section 3).

## 3. Changes made while finishing the merge

All decisions were made on the dev fold, on pages both compared runs could write, and checked on the two outside
benchmarks (the last three rows together change 42 RealDocBench documents and 2 olmOCR pages, with the same
scores). Check was used to find the misses, to explain the losses, and for reporting. Dev effects are changes of the subset mean (all
pages of the subset), relative to the merge as first fixed (forms before tables).

| change | dev | check | outside |
|---|---|---|---|
| `tier2_chart_options.draft_format: {underline: true}` | (makes fable_v4's reads replay) | 9 pages written again | - |
| forms before tables, `tier2_form_options.wide_blocks_geo: true` | (no new calls) | 2 pages written again | - |
| `tier2_form_options.clear_grid_blanks: true` | forms +0.02 (2 up), insurance +0.13 (2 up), 0 down | insurance +3.12 (5 up, 0 down) | same scores |
| `table_options.merge_strict` off | insurance +0.34, tables +0.20, dense -0.07 (4 up, 4 down) | insurance +2.32 (3 up) | same scores |
| `tier2_chart_options.table_figures` kept (frontier_v3) | turning it off: charts -0.32 (7 down, 1 up) | - | - |
| `tier2_chart_options.all_crops` off (fable_v4 behaviour) | no page changed | no page changed | same scores |

- **Chart drafts (`draft_format`).** The first mixed_v4 run (check 87.72) wrote no output for 8 chart pages and 1
  dense-table page. Their chart requests differed from fable_v4's cached ones only in the draft tables: fable_v4 runs
  `format_options.underline` on the OCRia-1 reading, so its drafts carry PDF-drawn `<u>` marks inside table cells,
  and mixed_v4's `underline_missing` leaves cells alone. The vector-hint cap was not the cause (`MAX_SERIES` is 12 in
  both branches), and neither was `allow_table_figures` (it acts after the read). The draft for the chart model is
  now formatted with fable_v4's options; the page keeps its own.
- **neon's last edits (01:44, tables before forms; the strict form trigger for geometry routing).** They change
  nothing on check insurance or financial. They ask for model calls neither parent made (a 122B table re-read on a
  form page; a form rewrite of the other reader's draft), so those pages score 0 without a GPU. Both are now
  switches (`tier2_table_options.before_forms`, `tier2_form_options.wide_blocks_geo: false`), off in mixed_v4
  (section 4).
- **Blank markers in data grids (`clear_grid_blanks`).** The form rewrite's prompt says that an empty field gets
  `[___]`, and the model also does that to the empty cells of data grids. On insurance filing exhibits it wrote
  27-249 cells holding only `[___]` (023cd5be_p5: 0.30 -> 1.00 once removed). In a data grid (header row, three or
  more rows, no checkbox), a cell holding only a blank marker is now emptied. The forms metric already reads `[___]`
  and an empty cell alike, and 13 changed form pages kept their scores.
- **`merge_strict`.** It keeps apart two side-by-side tables that each open with a full-width title row. On the dev
  pages it changes, the merges it blocks help more than they hurt (4 up, 4 down, net +0.47 over three table
  subsets). On check, the three
  insurance pages it held apart were one table split by the reading (0.22-0.26 -> 0.89-0.99).

## 4. Dropped, and why

- **Tier-2 tables before Tier-2 forms, and the strict form trigger for geometry routing** (neon's 01:44 edits). On
  the dev pages that can be scored they gain complex headers +0.24 and insurance +0.31 (3 up, 0 down). But they need
  model calls never made: on check, 3 Qwen3.5-122B strips and 1 Qwen3.8 form rewrite (2 pages); on dev, 9 strips and
  7 form rewrites in the first wave (10 pages). Each edit alone also needs new calls (3 and 7 of the 15 affected
  dev pages). They are worth a re-test once those calls are run.
- **`merge_strict`** (fable_v4 round 3): section 3.
- **frontier_v3's `all_crops` guard** (a per-chart page keeps its own reading unless every crop was read): no page
  changed on dev or check, and the outside scores are the same, so fable_v4's behaviour stays.
- **frontier_v3's `route_blanks`** (already left out by neon's merge): on dev, forms -0.11 (6 down, 1 up) against
  underline +0.50, headings +0.11, text +0.05. It also needs new form rewrites on 68 more dev pages.
- **fable_v4's page-level `underline: true`**: frontier_v3's `underline_missing` scores higher on check underline
  (94.45 vs 92.15). On dev, mixed_v4's underline is +0.94 over fable_v4.

## 5. Coverage and caveats

- Check, RealDocBench and olmOCR-bench: every case written, no cache miss.
- Dev (2,992 non-layout cases): 163 pages lack a cached call.
  - 112 of them fail the same way with fable_v4's own code: calls planned on the Linux VM, with chart crops and
    form drafts keyed by Linux renders. That is about 142 first-wave calls; three chart samples each make it about
    400, all Qwen3.8-27B but 3 strips and 1 PP-DocLayoutV3 call.
  - 51 are mixed_v4's own: 48 pages need frontier_v3's 122B table re-read (144 strips; frontier_v3's Tier-2 was only
    ever run on check), and 3 need 4 Qwen3.8 calls.
  - So the 122B table re-read has never been measured on dev. Dev comparisons above leave all 163 pages out.
- On dev pages both runs wrote, the merge as first fixed was above fable_v4 on text (+0.29), underline (+0.94),
  tables (+0.27), complex headers (+0.52), financial (+0.43), dense (+0.24), charts (+0.38) and fillable forms
  (+0.49). It was within 0.1 on the rest. frontier_v3 has no dev numbers to compare.

## 6. Reproduce

```
uv run python -m evalkit.fold_eval score --config configs/mixed_v4.yaml --fold check \
  --subsets text,headings,strikeout,underline,tables,complex_table_headers,financial_tables,insurance_filing_tables,dense_tables,charts,forms,fillable_forms \
  --name mx-chk-final --workers 4
uv run python -m evalkit.fold_eval score --config configs/mixed_v4.yaml --fold check --subsets layout \
  --set tier2_charts=false --set tier2_forms=false --set tier2_tables=false --name mx-chk-lay-final
uv run python -m evalkit.ext_eval write --bench realdoc --config configs/mixed_v4.yaml --name mx-rd-final
uv run python -m evalkit.ext_eval write --bench olmocr --config configs/mixed_v4.yaml --name mx-olm-final
uv run python -m evalkit.ext_eval score --bench realdoc --name mx-rd-final --name mx-rd-fable4 --name mx-rd-fv3new
```

For olmOCR-bench, score with the view in an `mx-` folder: `ext_eval score` builds its view inside the first named
run's folder.
