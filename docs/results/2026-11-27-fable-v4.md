## 2. What changed, and the evidence for each change

### 2.1 Reader selection on born-digital pages (`select_options.layer_margin: 0`, no GPU)

Chandra-OCR-2 and OCRia-1 fail on different pages: on the dev sample a perfect per-page choice between the two
pipelines is worth +2.9 on the five text-side dimensions. On a page with a healthy, visible PDF text layer the layer
itself says which reading is better: `fixes/select.py` scores each reading by the mean of its word F1 and its number
F1 against the layer and keeps OCRia-1's reading when it scores higher (first built with a 0.03 margin; a sweep of
0 / 0.008 / 0.015 / 0.03 / 0.06 on the dev fold favoured no margin: text 87.82 / - / 87.46 / 87.39 / -, forms 82.31 /
82.23 / 82.03 / 81.84 / 81.27). Pages without such a layer, pages with formulas and pages where Chandra drew a
chart figure are never switched.

- Dev sample (578 pages): text 83.31 -> 85.49, forms 78.95 -> 79.74, tables 90.80 -> 90.92.
- Whole dev fold, together with 2.2 (2,874 pages, no tier-2): text +0.46, formatting +0.99, tables +0.27, forms +1.72.

### 2.2 Underlines from the PDF's own drawing (`format_options.underline: true` + `pdf/drawings.py`, no GPU)

The existing underline option marked table borders, heading rules and a word processor's dashed change-tracking
leaders as underlines, so it had been left off. A line now counts as an underline only if it does not overrun its
text by more than two character heights, does not run under three or more columns, and is not dashed.

- Against the reference on all 95 dev underline pages: precision 0.56 -> 0.84, recall unchanged at 0.95.
- Dev underline slot 81.2 -> 92.3; no page down. On 470 outside pages the underlined characters fell from 13,228 to
  4,883, and the removed ones inspected were table and form borders.
- Restoring bold and italic from PDF font names was measured and rejected: the fonts say bold, the references do not
  count it (figure labels, link text), and making it score would have meant fitting exclusions to the references.

### 2.3 Table structure repairs from the text layer (`table_options`: squeeze, sign, head_fill, last_column, merge_apart, merge_strict; no GPU)

All act only on pages with a healthy text layer and keep the reading when the evidence is unclear: a value written
once more than its line prints is dropped and two grid columns whose words share one printed column are merged; a
constant currency-sign column joins its amounts; missing trailing header cells and a last column every body row
prints are added from the layer (the words must show ink on the page image); table halves separated by other tables
are joined when the rows line up, and two tables that each carry a title row are kept apart.

- Dev sample tables dimension 90.80 -> 91.17 (9 pages up, 0 down); on the other 1,078 dev table pages 17 up, 0 down.
- Left out as benchmark-only: joining or splitting multi-line cells into rows (two references want opposite things),
  header grouping by meaning, dropping a table re-read from a chart.

### 2.4 Tier-2 reads on Qwen3.8-27B-FP8 instead of Qwen3.5-122B / 27B

Qwen3.8-27B (released 2026-11-07, Apache-2.0) fits one 96 GB GPU, so two servers run side by side where the 122B
model needed both cards.

**Charts** (`tier2_chart_options`): thinking on (temperature 0.6), prompt `v2b`, small crops enlarged to 2048 px,
vector measurements up to 10,000 characters, plain re-read when the thinking read runs out of tokens.

| dev sample, 86 chart pages | chart score |
|---|---:|
| no tier-2 read | 83.21 |
| Qwen3.8, no thinking, original prompt | 86.81 |
| Qwen3.8, thinking, original prompt | 88.28 |
| + crop zoom only | 89.26 |
| + full vector measurements only (the hint was cut at 2,500 characters, losing most series of a dense chart) | 89.06 |
| + prompt `v2b` only | 90.75 |
| all three (82 pages every variant wrote) | 89.25 vs 90.96 for `v2b` alone |

`v2b` is the original prompt plus two rules: every plotted mark gets a number (printed label, else vector
measurement, else read off the axis; the original "never invent" wording made the model return empty tables for
unlabelled series), and one column per series (it had written two series into one cell). A rewritten prompt (`v3`)
scored lower (87.43) because it dropped per-panel titles, and was abandoned. Run-to-run variance at temperature 0.6
is about one point on 86 pages: the variants above are not separable from each other, only from the first three rows.

**Forms** (`tier2_form_options.prompt: kv`): on the failing dev forms the values were read correctly but detached
from their captions (a printed box number between caption and value, fields laid out as loose table cells). The
form step now asks the model to rewrite the page as `caption: value` lines from the page image, the draft and the
text layer's lines; it may answer `NOT_A_FORM`; the rewrite must keep 93% of the draft's words and every data grid
(a header, three or more rows, mostly filled). The trigger also fires on a single checkbox, runs of blanks, or three
or more one- or two-row tables. A first, wider trigger (tables with many empty cells) rewrote real tables and cost
two points on the tables dimension; it was removed before any full run.

- Dev sample forms dimension: 78.95 -> 82.00 (with selection); thinking adds about +1.2 on the forms slot.

### 2.5 Three chart reads voted cell by cell (`tier2_chart_options.samples: 3`)

A value read off an axis carries reading noise. Each chart is read three times (seeds), and where the reads agree
on the table's shape and labels each number becomes the median of the three (always one of the values read).
Dev sample charts 88.94 -> 89.48 (6 pages up, 1 down); all 568 chart pages 87.58 -> 87.94.

### 2.6 What the outside benchmarks changed

- **Pictures.** When the selector kept OCRia-1's reading, the content Chandra transcribes from figures and diagrams
  was lost (RealDocBench chart group 87.4 -> 82.9). Now Chandra's transcription of each non-chart picture of 25
  words or more is carried over as image alt text (`select_options.keep_pictures`): RealDocBench charts 88.0,
  ParseBench unchanged.
- **Running headers and footers.** With `strip_furniture` (olmOCR-bench), furniture was only removed from
  Chandra's reading; kept OCRia-1 readings brought it back (headers_footers 88.6 -> 58.0). The lines Chandra labels
  as furniture are now also dropped from the other reading, matching the page's first and last four lines loosely.
- **Formulas.** The layer-fit comparison is not meaningful on formula pages; the selector skips them
  (`select_options.skip_math`). Costs 0.1 on ParseBench overall.
- **Scan judge off.** On a prose page without a text layer, a Qwen3.8 transcription can decide which of the two
  readings to keep (`select_options.judge`). ParseBench text +0.6 (dev +0.95), but RealDocBench 94.42 -> 94.23 and
  olmOCR-bench 84.91 -> 84.72 with it on. It is implemented and off.
- **The form step on either reader** (`tier2_form_options.any_reader`): pages where the selector kept OCRia-1's
  reading were skipping the form rewrite; forms 84.88 -> 86.52 on all pages.

## 3. Tried and dropped

- **Qwen3.8-27B as a third page reader.** Read alone (plain prompt, no thinking) it is the weakest of the three on
  the dev sample (five-dimension mean 79.2 against 85.6 for Chandra and 86.0 for OCRia-1): much worse on charts
  (61.4) and dense tables (77.6), worse on scanned text (68.4 against 74.2 / 76.2), better only on financial tables
  (90.3 against 86.4). A perfect per-page choice among the three would add +1.3 over the two-reader oracle, but no
  cheap selector found it: text-layer fit, table-grid alignment and agreement voting all landed within 0.4 of the
  two-reader selector. Dropped as a reader; see the judge note below.
- **Chart prompt rewritten from scratch (`v3`).** 87.4 against 88.3: it named single series by their unit and
  dropped per-panel title lines. The two rules that fixed the zero-score pages were added to the original prompt
  instead (`v2b`).
- **Agreement voting between chart reads.** Keeping, per page, the chart read that agrees most with the others
  scored 87.7-88.5 against 88.3 for the best single read (oracle 91.0).
- **Wide form trigger (tables with many empty cells).** Forms +1.2 but tables -2.1: it rewrote real tables as
  forms. Removed.
- **Bold / italic from PDF font names.** See 2.2.
- **Layout.** Check loss splits into elements not located (5.5 points), located with mismatching text (3.1), loose
  boxes (2.7) and extra boxes (1.4). No general fix was found in the time available; the layout code is unchanged.
- **Qwen3.8 strip re-reads of dense tables.** Tables +0.25 on dev without them; `tier2_tables` is off.
- **LightOnOCR-3-4B as a third reader for scans.** Text +0.08, formatting -0.24 on dev.
- **Restoring text-layer lines the reader skipped.** 0 pages up, 97 down on dev text: the restored lines count as
  inserted words against the reference. Reverted.
- **Vector snapping after a tier-2 chart read, a draft-versus-tier-2 chart guard, Chandra's layout blocks as extra
  layout boxes, a looser form-rewrite word threshold.** No measurable effect on dev.

## 4. Protocol and caveats

- Pilots ran on a fixed, stratified 652-case dev sample (`runs/fable90/dev_sample.ids`); zero-GPU changes were
  confirmed on the whole dev fold. Check was scored for the final config and for two intermediate ones
  (`v4-final`, `v5-final`); no decision was taken from a check number.
- The outside benchmarks did change decisions, on purpose: RealDocBench showed the selector dropping picture
  content (fixed by carrying Chandra's picture transcriptions over), olmOCR-bench showed running headers surviving
  when the other reading is kept and the selector hurting formula pages (fixed by the loose furniture match and the
  math guard). Those two benchmarks are therefore no longer untouched by this work; they are still independent of
  ParseBench 2.
- Chart reads run at temperature 0.6: a rerun from an empty cache moves the charts dimension by about a point on
  small samples. Reported numbers are one cached run.
- PDFium rasterises about 16% of the pages a shade differently on Linux than on macOS, and request keys hash
  pixels. `evalkit.pixel_alias` maps page identities so both machines share one cache for page-level calls; chart
  crops still hash differently, so the chart calls made on the Linux VM replay there, not on the Mac.

## 5. Reproducing

- Plan and score any config on a fold: `python -m evalkit.fold_eval plan|score --config configs/fable_v4.yaml
  --fold check|dev|all --name <run>`; outside benchmarks: `python -m evalkit.ext_eval plan|write|score`.
- Serving: `vllm serve Qwen/Qwen3.8-27B-FP8 --revision c3a462cc3d38cf351f3b26cbd763469eeb74ef81` (one per GPU),
  manifests run with `python -m serve.vm_run`. Run `vllm download-kernels` first, or generation is slow.
- Layout is scored with the same config and the Tier-2 options off (layout items do not depend on them).

**Where the remaining headroom is (dev fold, no GPU).** No open-weight entry on the public leaderboard beats this

reader pipelines would add about 2.0 to the overall score on dev: text +0.95 on born-digital pages and +1.9 on

**Kept (in `configs/fable_v4.yaml`).**

- `select_options.fuse_words`: where the two readings disagree on plain words and every word of the other

  (10 pages up, 0 down); check text 90.15 -> 90.26 (4 up, 0 down) with text formatting 91.47 -> 91.42 (1 down);

- Underlines: a table where lines run under two or more cells of at least 60% of the rows (three rows or more) is
  a ruled table, and none of those lines is an underline. Dev underline 90.62 -> 91.23 (1 page up, 0 down); check

## 7. A jury of other open readers (stand-in result, no GPU)

Idea taken from the literature on combining OCR models (Consensus Entropy, CVPR 2026: agreement among several
independent readers identifies the reliable output; the minimum-Bayes-risk choice "keep the candidate closest to the
others"). Our two readings are the candidates; other open-weight models' readings of the same page are the jury;
the candidate the jury's readings resemble more is kept. The jurors' readings were not produced here: they are the
per-page outputs those models' authors published for the leaderboard (`llamaindex/ParseBench-2-results`), imported
as stand-in calls with `evalkit.standin.import_juror`. **So every number in this section is a stand-in number on
benchmark pages only; it becomes a result when the juror models are run by the pipeline and the outside benchmarks
are scored.** Jurors: LightOnOCR-3 4B, dots.mocr, Infinity-Parser2 Pro, Surya 2, MinerU2.5 Pro, Qwen3.8-27B
(thinking).

**Offline, on the two reader pipelines' own per-page scores (dev):**

| Similarity used by the jury | text | complex-header tables | financial tables |
|---|---:|---:|---:|
| none (text-layer rule; Chandra on scans) | 88.08 | 75.35 | 91.12 |
| the benchmark's own page metric with a juror in the reference seat | 90.02 | 76.70 | 92.56 |
| in-house: words, digit tokens, word pairs (`reading_similarity`) | 89.58 | - | - |
| in-house with table records (`page_similarity`) | - | 75.26 to 76.30 | 91.35 to 92.05 |
| perfect choice | 90.95 | 79.61 | 94.03 |

One juror alone gives most of the text gain (LightOnOCR-3 4B 89.67, dots.mocr 89.67, Qwen3.8 thinking 89.73 with the
benchmark's metric). Forms do not move (80.38 -> 80.16 to 80.43). The in-house table similarity does not reproduce
the table gain reliably (the result changes sign with the margin), so the jury is not applied to pages with tables;
using the benchmark's scorer as the similarity inside the parser was not considered acceptable.

**Through the pipeline** (`configs/fable_v5_jury_standin.yaml`: jury on non-tabular pages without a text layer,
in-house similarity, margin 0), local cache replay:

| | fable_v4 | + jury (stand-in) |
|---|---:|---:|
| dev text | 87.42 | 88.47 (36 pages up, 9 down) |
| dev formatting, text pages | 91.40 | 91.19 |
| check text | 90.26 | 90.48 (10 up, 1 down) |
| check formatting, text pages | 91.42 | 91.46 |

Applying the jury on born-digital pages as well gives dev text 88.61 but costs strikeout 0.9 and underline 0.5, so
it stays on scans. On the held-out fold this is about +0.04 overall (88.63 -> about 88.67); on dev about +0.15.

To turn this into a result: add adapters for one or two juror models (a LightOnOCR-3 adapter exists), run them on
all pages and on RealDocBench and olmOCR-bench, and keep the jury only if the outside benchmarks do not lose.
