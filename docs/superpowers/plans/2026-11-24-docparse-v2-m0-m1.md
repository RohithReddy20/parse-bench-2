# docparse v2, M0 and M1: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reproduce OCRia-1's ParseBench 2 score (85.24) from its published outputs with no GPU, build its
loss table, and stand up the foundations (M0); then reproduce the score from our own OCRia-1 run and swap in
better layout boxes (M1).

**Architecture:** OCRia-1's page answer is parsed into a lossless block IR and written back out; correctors
(later milestones) add candidates behind flags. Every model call is content-addressed and cached, so scoring
is CPU-only. `evalkit` owns pins, data, scoring, the ledger and the loss table; `docparse` never imports it
or the harness.

**Tech Stack:** Python 3.12, uv, hatchling, pydantic 2, pypdfium2, Pillow, zstandard, SQLite, pytest, ruff.
`parse-bench` (harness) pinned by git commit. Modal and vLLM ≥ 0.30 for OCRia-1 in M1.

**Spec:** `docs/superpowers/specs/2026-11-24-docparse-v2-design.md` (revision 2). Scoring rules:
`docs/research/2026-11-23-parsebench2-research.md`. Kept architecture detail:
`docs/research/2026-11-24-fable-architecture-plan.md` §1.3, §1.5–1.9, §3.

## Review Focus

Failure modes the spec implies but that no milestone gate exercises. Each has a test in the task named.

1. **Truncated or empty OCRia-1 answer** (`finish_reason=length`, unclosed `<table>` or code fence, empty
   string): the page still parses and writes, with the unbalanced block carried as opaque. Task 7.
2. **Interrupted or concurrent cache write** (killed mid-write, two processes writing one key): no partial
   file is ever readable, and the first complete write wins. Task 8.
3. **PDFs the benchmark doesn't contain** (several pages, rotated pages, CropBox smaller than MediaBox, an
   image file, corrupt or encrypted bytes): one output page per input page in the displayed frame; a clear
   `ParseError` for unreadable bytes. Task 10.
4. **Hostile published records** (`example_id` with `..` or an absolute path, a missing field, a huge line):
   rejected with the record's line number; nothing is written outside the output root. Task 3.
5. **Large-format sheets** (page area × scale² over 80,000,000 pixels): rendered below 300 DPI as the harness
   does, and layout boxes still convert to PDF points with the page's own scale. Task 10.

### Task 6: OCRia-1 loss table

**Files:**
- Create: `src/evalkit/losses.py`, `docs/results/2026-11-24-ocria1-loss-table.md`
- Modify: `src/evalkit/__main__.py` (command `losses --run <id> [--fold dev|check|all]`)
- Test: `tests/evalkit/test_losses.py`

**Interfaces:**
- Consumes: `Ledger.cases`, `parse_bench.evaluation.metric_policy.{MetricPolicy, score_metric, PAPER,
  METRIC_KEYS}`, `next_score.NEXT_DIMENSIONS`.
- Produces: `loss_table(ledger, run_id, fold="all") -> list[LossRow]` with
  `LossRow(dimension, subset, metric, label, severity, pages, dim_points, overall_points)`, and
  `render_markdown(rows) -> str`.
- Definitions (all on the 0–100 scale of the dimension; `overall_points = dim_points / 6`):
  - page weight `w = slot_weight / pages_in_subset × 100`;
  - for capped metrics, `parsing` is the bound `score_metric` uses (`proportional`, and for formatting and
    forms `min(proportional, coverage / 0.5)`);
  - row `content (not recovered)`: `Σ w × (1 − parsing)`;
  - row `severity cap`: `Σ w × (parsing − score)`;
  - one row per event label: the counterfactual gain `Σ w × (score_metric(metadata, policy with that label
    set to "ignore") − score)`. Where the saved metadata holds only severity counts (text, formatting), the
    label is `all <severity> errors`, plus the two reading-order labels for text. These rows explain the cap
    row and are not additive;
  - layout has no cap: rows are the metric's own per-element failure reasons, weighted by its element
    weights. Read the reason and weight field names from a real `layout` report before writing the code.
- Two invariants, tested on the real run:
  1. `score_metric(metric, metadata, paper_policy) == score` within 1e-6 for every capped case (proves the
     counterfactual machinery is called correctly); mismatches are counted and listed, never hidden.
  2. Per dimension, `content + severity cap` (or the layout reason rows) sums to `100 − dimension score`
     within 0.02.

  gives the expected counterfactual per label; a case where `proportional` binds gives zero cap loss; page
  weights for `tables` use 1/2 and `dense_tables` 1/8.
